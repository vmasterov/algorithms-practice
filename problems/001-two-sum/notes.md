# 001. Two Sum — разбор

**Паттерн:** хеш-таблица («запомни, что видел, и ищи дополнение»)
**Итоговое решение:** один проход, Map `значение → индекс`
**Сложность:** время O(n), память O(n). Brute force: время O(n²), память O(1)

## Ключевая идея
Для каждого `x` нужное второе число известно заранее: `target - x`.
Задача сводится к вопросу «встречалось ли оно раньше?», а хеш-таблица отвечает на него за O(1).
Если проверять дополнение **до** записи текущего элемента, получается один проход,
и элемент не может образовать пару сам с собой.

## Угловые случаи
- `[0, 0], 0` — нули и индекс `0` (ловушка JS: проверять `!== undefined`, а не на истинность)
- `[3, 3], 6` — дубликаты
- `[3, 2, 4], 6` — элемент нельзя использовать дважды (`[0, 0]` — ошибка)
- `[5, 1, 9], 10` — пара не соседняя
- `[-1, -2], -3` — отрицательные числа

## Где застрял / что исправили
- Шаг «уточнить условие» пропущен. Первые угловые случаи противоречили условию
  (нет ответа, несколько ответов) — это и были вопросы, которые нужно задать интервьюеру.
- Не было случая «элемент + он же сам».
- Оптимизацию нашёл после подсказки про хеш-таблицу. До одного прохода дошёл сам,
  после наводящего вопроса.
- TS: `Map.get` возвращает `number | undefined` — исправлено одним `get` и проверкой на `undefined`.
- Имена: `numsHashKey` / `numsHash` → `complement` / `seen`.

## Оценка
| Критерий | Оценка |
|---|---|
| Анализ условия | 3/5 — уточняющие вопросы пропущены |
| Угловые случаи | 3/5 — со второй попытки корректные, но без «сам с собой» |
| Код | 5/5 — корректный, после правки типов и имён |
| Сложность | 5/5 — верно, включая память |
| Время | не замерено (сессия растянулась на 2 дня) |

**Подсказок использовано:** 2 (хеш-таблица, один проход)

## На будущее
- Всегда начинать с вопросов: «а если ответа нет?», «а если их несколько?», «могут ли быть дубликаты?».
- Называть сложность по памяти вместе со временем.
- Засекать время на задачу.
