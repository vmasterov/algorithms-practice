# 002. Binary Search — разбор

**Паттерн:** бинарный поиск (два указателя `left`/`right`, отбрасываем половину на каждом шаге)
**Итоговое решение:** итеративный, условие цикла `left <= right`
**Сложность:** время O(log n), память O(1). Brute force: время O(n), память O(1)

## Ключевая идея
Массив отсортирован, поэтому одно сравнение с серединой говорит, в какой половине может быть ответ.
- `nums[middle] > target` → ответ слева: `right = middle - 1`
- `nums[middle] < target` → ответ справа: `left = middle + 1`
- `left > right` → диапазон пуст, числа нет: `-1`

`± 1` обязательно: середина уже проверена, без сдвига возможен бесконечный цикл.

## Середина
- `Math.floor((left + right) / 2)` — в JS достаточно.
- `left + Math.floor((right - left) / 2)` — канонический ответ на вопрос о переполнении (Java/C++).
- Решение использовало `Math.floor(left / 2 + right / 2)` — корректно, эквивалентно первому варианту.

## Угловые случаи
Свои: `[0], 1` (промах в одном элементе), `[-4..0], 0` (последний элемент),
`[-9999, 0, 9999], 1` (числа нет между соседями).
Стоило добавить: target на индексе 0, target меньше всех / больше всех, массив чётной длины (`[1, 2]`).

### Зачем нужны эти случаи
Это входы, на которых чаще всего ломаются границы `left` / `right` / `middle`. Каждый ловит свой класс ошибок:

| Случай | Пример | Что ловит |
|---|---|---|
| Первый элемент | `[1, 3, 5, 7], 1` | `right` должен опуститься до `0`. Ловит недоход до края (`<` вместо `<=`) |
| Последний элемент | `[1, 3, 5, 7], 7` | `left` должен дойти до `n - 1`. Ловит `right = nums.length` вместо `nums.length - 1` |
| Вне диапазона слева | `[1, 3, 5], -10` | `right` уходит в `-1`: цикл должен завершиться и вернуть `-1`, без обращения к `nums[-1]` |
| Вне диапазона справа | `[1, 3, 5], 100` | То же, но `left` уходит за конец массива |
| Длина 1 | `[5], 5` и `[5], 3` | `left === right` сразу: цикл должен выполниться хотя бы раз (с `<` упадёт) |
| Длина 2 | `[1, 2], 2` | Середина округляется вниз на первый элемент: без `+ 1` в `left = middle + 1` — бесконечный цикл |

Общая схема для любой задачи с индексами: **края массива + отсутствие ответа + минимальные размеры**.
