# 003. Valid Parentheses — разбор

**Паттерн:** стек (последняя открытая — первой закрывается, LIFO)
**Итоговое решение:** массив как стек + Map «закрывающая → открывающая»
**Сложность:** время O(n), память O(n). Brute force (удалять пары `()[]{}`, пока можно): время O(n²)

## Ключевая идея
Закрывающая скобка всегда должна совпасть с **последней незакрытой** открывающей — это ровно вершина стека.
- открывающая → push
- закрывающая → вершина стека должна быть её парой, иначе `false`; если да → pop
- в конце стек должен быть пуст (иначе есть незакрытые)

## Почему O(1) по памяти невозможно
Нужно помнить порядок **всех** незакрытых открывающих (до n/2 штук), чтобы проверить, например, `([{…}])`.
Счётчик вместо стека работает только для одного типа скобок.
Попытка с указателями `previous` / `offset` ломалась в обе стороны:
- принимала неверные: `((`, `)(`, `{}[}`, `(){)`;
- отвергала верные: `()[{}]`, `()[[]]`, `{}(())`.

## Угловые случаи
Из решения (16 кейсов): одиночные `(` и `)`, только открывающие `((`, только закрывающие `))`,
лишняя скобка в конце `())` / `()(`, в начале `)()`, перекрёстные `([)`, `(])`,
последовательность `()[]`, вложенность `{([])}`, `((()))`, вложенность + хвост `((()))(`.
Хорошее покрытие.

## Где застрял / что исправили
- Сначала искал O(1) по памяти и докручивал указатели — тупиковый путь, ушло много времени.
- Описанный изначально «brute force» на массиве и был оптимальным решением.
- В тестах ожидаемый ответ для `()[{}]` был подогнан под код (`false` вместо `true`).
  **Правило: ожидаемый ответ берётся из условия, не из решения.**
- Несовпавшая закрывающая сначала клалась в стек вместо раннего `return false` —
  исправлено, добавлен ранний выход для нечётной длины.
- В описании п. 4: «длина, приведённая к boolean» — это инверсия; в коде верно (`length === 0`).
- Мелочь: `let char` → `const`.
