# 004. Valid Palindrome — разбор

**Паттерн:** два указателя (с концов навстречу друг другу)
**Итоговое решение:** `isPalindrome1` — указатели `left`/`right`, пропуск не букв/цифр через `continue`
**Сложность:** время O(n), память O(1). Первое решение (match + reverse + join): время O(n), память O(n)

## Ключевая идея
Палиндром сравнивает только **симметричные** позиции — значит, достаточно помнить два индекса.
- левый символ невалиден → `left++`, `continue`
- правый символ невалиден → `right--`, `continue`
- оба валидны → сравнить в нижнем регистре; не равны → `false`; равны → сдвинуть оба
- `left < right` (не `!==`): при чётной длине указатели перепрыгивают друг через друга

`continue` после пропуска удобен: если пропуски сведут указатели, условие цикла проверится сразу.

## Контраст с 003
Вопрос «что минимально нужно помнить?»:
- 003 (скобки) — порядок всех незакрытых → O(n), O(1) невозможно;
- 004 (палиндром) — только текущую пару позиций → O(1).

## JS-ловушка
`re.test()` с флагом `/g` хранит `lastIndex` между вызовами и даёт «плавающие» результаты.
Для посимвольной проверки — регулярка **без** `/g` (как в решении).

## Угловые случаи
Из решения: только пробел, только знаки препинания, один символ (буква/цифра), разный регистр `aAa`,
цифры `1 -2`, примеры из условия.
Стоит добавить: `"0P"` (цифра vs буква, `false`), чётная длина `"abba"`, `"ab"`.
Проверено на 1 млн случайных строк против эталона — расхождений нет.

## Где застрял / что исправили
- Сначала вышел за условие (кириллица); диапазон `а-я` не включает `ё` → `"ёа"` давал `true`. Вернулся к ASCII.
- Оптимизацию хотел пропустить — а в ней суть задачи. Подсказка: два указателя, O(1) достижимо.
- План двух указателей: `l !== r` (ломается на чётной длине), нет сдвига после совпадения,
  правый указатель должен идти `--`. **В коде все три пункта исправлены.**
- Комментарий-описание в файле остался старым (кириллица, `l !== r`) — описание и код снова разошлись (3-й раз).
