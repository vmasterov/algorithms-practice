# 005. Best Time to Buy and Sell Stock — разбор

**Паттерн:** один проход с «лучшим значением слева» (минимум цены до текущего дня)
**Итоговое решение:** `min` / `max` / `profit`, при новом минимуме `max` сбрасывается
**Сложность:** время O(n), память O(1). Brute force (все пары i < j): время O(n²), память O(1)

## Ключевая идея
Для каждого дня продажи лучшая покупка — **минимальная цена до этого дня**.
Значит, достаточно идти слева направо, помнить минимум и на каждом шаге считать `price - min`.

Сброс `max = price` при новом минимуме обязателен: старый максимум был **до** покупки,
продать по нему нельзя. Без сброса `[5, 10, 1]` дал бы прибыль 9.

## Упрощение
Переменная `max` не нужна: на каждом шаге `profit = Math.max(profit, price - min)`.
Меньше состояния — меньше мест для ошибки. Решение с `max` при этом корректно.

## Угловые случаи
Из решения: примеры из условия, один день `[1]`, равные цены `[1, 1]`, ноль в цене `[0, 1]`,
минимум в самом конце `[1, 2, 3, 0]`, `[0, 1, 3, 2, 0]`.
Стоит добавить — ключевые для «нового минимума позже»:
- `[3, 8, 1, 10]` → 9 (новый минимум даёт **большую** прибыль);
- `[2, 4, 1, 2]` → 2 (новый минимум даёт **меньшую** прибыль, старый ответ сохраняется).
Проверено на 450 тыс. случайных массивов против brute force — расхождений нет.

## Где застрял / что исправить
- Подсказок не было.
- Уточняющие вопросы (`[1, 1, 1]` → 0? длина 1 → 0?) — оба ответа есть в условии
  («если заработать нельзя — 0», продажа в «другой, более поздний день»).
- В описании оптимизации нет главной строки — сброса `max` при новом минимуме. В коде он есть.

## На будущее
- Перед вопросом интервьюеру — перечитать условие: нет ли ответа там.
