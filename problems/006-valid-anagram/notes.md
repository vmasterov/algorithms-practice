# 006. Valid Anagram — разбор

**Паттерн:** хеш-таблица / подсчёт частот
**Итоговое решение:** Map «буква → количество»: +1 по `s`, −1 по `t`, ноль → удалить ключ
**Сложность:** время O(n), память O(1)* — см. ниже. Brute force (findIndex + удаление): время O(n²)

## Ключевая идея
Анаграмма = одинаковые частоты букв. Посчитать частоты одной строки и «погасить» их второй.
Ранние выходы: разная длина → `false`; буквы `t` нет в Map → `false`.

## Память: O(n) или O(1)?
По условию только строчные латинские буквы — в Map не больше **26** ключей, независимо от длины строки.
Поэтому память O(1) (точнее, O(k), k = размер алфавита). Это частый вопрос на собесе.
Отсюда же альтернатива: массив из 26 счётчиков с индексом `char.charCodeAt(0) - 97` — быстрее Map.
Follow-up «а если Unicode?» — тогда только Map (алфавит неограничен), и решение уже готово:
`for...of` идёт по кодовым точкам.

## Другие подходы
- Сортировка обеих строк и сравнение: время O(n log n). Короче в коде, но медленнее.
- Brute force из решения: в JS строки неизменяемы, превращение в массив — уже O(n) памяти,
  так что вариант «O(1), если мутировать исходный объект» здесь не работает.

## Наблюдение
При равных длинах финальная проверка `size === 0` всегда истинна: если каждая буква `t` нашлась
в Map, а длины совпадают, Map опустеет. Проверка безвредна, но избыточна.

## Угловые случаи
Из решения: разные длины в обе стороны (`a`/`aa`, `aa`/`a`), одна буква, повторы `aaa`,
те же буквы в разном количестве `bab`/`aba`, отличие в одной букве `abb`/`abc`.
Хороший набор. Проверено на 500 тыс. случайных пар против сортировки — расхождений нет.
