# 007. Maximum Average Subarray I — разбор

**Паттерн:** скользящее окно фиксированного размера
**Итоговое решение:** `findMaxAverage1` — сумма окна: +новый, −выпавший; сравниваем суммы, делим на `k` один раз в конце
**Сложность:** время O(n), память O(1). Brute force (пересчёт каждого окна): время O(n·k)

## Ключевая идея
Соседние окна отличаются двумя элементами: один входит, один выходит.
Значит, сумму не нужно пересчитывать — достаточно `sum += nums[i]`, `sum -= nums[i - k]`.
`k > 0`, поэтому окно с максимальной суммой = окно с максимальным средним → делить один раз.
Начальное значение — `-Infinity`, не `0`: все числа могут быть отрицательными.

## Дробный ответ
«Погрешность до 10^-5» — дроби в компьютере неточны (`0.1 + 0.2 = 0.30000000000000004`).
Сумма целых считается точно; одно деление в конце даёт ровно ожидаемое значение.
Если обновлять само среднее (дроби), ошибки копятся → для сравнения в хелпере нужна нормализация (округление).

## Что было не так
1. **Особый случай `k === 1` через сортировку:** не нужен (окно и так работает при `k = 1`),
   O(n log n) против O(n), и `sort` **мутировал входной массив** вызывающего кода. Убран.
2. **Вторая версия:** `prevSum - nums[i - k]` без присваивания — выпавший элемент вычитался
   только для сравнения, а в сумме оставался. `[0, 1, 9, 9], k = 1` → 10 вместо 9. Исправлено.
3. Тесты не поймали ошибку 2: во всех кейсах окно сдвигалось максимум один раз.

## Угловые случаи
Из решения: пример из условия, `k === n` (`[0], 1`, `[-1, -2], 2`), все отрицательные,
лучшее окно в начале `[-1, -2, -3], 2` и в конце `[-1, -2, 3], 2`, `k = 1`.
**Обязательно для окна:** кейс, где окно сдвигается ≥ 2 раз (`n ≥ k + 2`) — добавлен `[0, 1, 9, 9], 1`.
Обе финальные версии проверены на 300 тыс. случайных массивов против brute force.

## Оценка
| Критерий | Оценка |
|---|---|
| Анализ условия | 4/5 — уточнил непонятное (погрешность) |
| Угловые случаи | 3/5 — хорошие по значениям, но без двойного сдвига окна |
| Код | 4/5 — первая версия верна после удаления `k === 1`; вторая — после правки |
| Сложность | 4/5 — O(n)/O(1) верно, но ветка `k === 1` противоречила оценке |
| Время | 2/5 — ~2 часа, в 3 раза выше цели |

**Подсказок использовано:** 1 (причина ошибки во второй версии)
