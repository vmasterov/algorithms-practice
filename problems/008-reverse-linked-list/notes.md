# 008. Reverse Linked List — разбор

**Паттерн:** связный список, три указателя (`prev` / `current` / `next`); рекурсия
**Решения:** итеративное, хвостовая рекурсия, классическая рекурсия — все три верны
**Сложность:**
- итеративное — время O(n), память O(1)
- обе рекурсии — время O(n), память O(n) (стек вызовов)

## Итеративно
Каждый шаг: запомнить хвост → перецепить → сдвинуться.
`next = current.next` → `current.next = prev` → `prev = current` → `current = next`. Ответ — `prev`.
Новых узлов не создаётся: переменные — это ссылки на те же объекты, мы только меняем `next`.

## Хвостовая рекурсия `(prev, current)`
Тот же цикл, но `prev` и `current` передаются аргументами. База: `current === null` → вернуть `prev`.
В JS (V8) хвостовые вызовы **не** оптимизируются → стек всё равно растёт.

## Классическая рекурсия `(current)`
- База: `current === null || current.next === null` → вернуть `current` (это и есть новая голова).
- Шаг: `head = f(current.next)` — голова снизу, **не трогаем, передаём наверх**.
- Хвост развёрнутой части — `current.next` (старая связь ещё цела) → `current.next.next = current`.
- `current.next = null` на каждом шаге: у бывшей головы так и останется, у остальных перезапишет уровень выше.

## Проверка
Все три версии сравнены с `[...a].reverse()` на 50 тыс. случайных списков (вкл. пустой) — без расхождений.
5000 узлов (максимум по условию) — все работают.
200 000 узлов — обе рекурсии падают с `RangeError: Maximum call stack size exceeded`, итеративная — нет.

## Ошибки по пути
- Итеративный план: `next = current.next` до проверки на `null` (падение на пустом списке);
  особый случай для первого узла → цикл `1 ↔ 2`; потеря хвоста при `current = current.next` после перезаписи;
  `return current` вместо `prev`.
- Классическая рекурсия: каждый уровень возвращал `current` → голова терялась;
  потом `return head` в базе (в JS — ещё и `ReferenceError` из-за TDZ у `let head`).
- `getListFrom` переписан на фиктивный узел (dummy) — ушли `current!`.

## Мелочи
- В комментарии у хвостовой рекурсии `=> void`, а функция возвращает голову.
- `test` вызывается только для классической версии — стоит прогонять все три.

## Оценка
| Критерий | Оценка |

| Анализ условия | 5/5 |
| Угловые случаи | 5/5 — пустой, 1, 2, повторы, отрицательные |

## На будущее
- Указатели в списках: проверять план на `[]`, `[1]`, `[1, 2]` — там видны все ошибки.
- Рекурсия: сначала база, потом «поверь, что вызов вернул правильный результат для хвоста — что сделать с текущим?».
